# 3D 空间站交互场景任务拆解（交互原型版）

> 文档状态：已完成部分交互原型的历史记录。外部真实感重制的最新任务以 `3d-space-station-exterior-realism-task-breakdown.md` 为准；本文件中的程序化灰盒任务不能替代 V2 外观资产验收。

本文基于 `3d-space-station-interactive-plan.md`，目标是先完成：

```text
真实感三舱外部总览
  -> 点击舱段文字或模型热点
  -> 镜头过渡
  -> 显示对应舱段内部灰盒/模型
  -> 返回总览
```

本阶段不做零重力移动、实验任务、机械臂控制、账号和后端服务。

## 1. 任务优先级和依赖关系

| 优先级 | 任务组 | 目标 | 依赖 |
|---|---|---|---|
| P0 | 资料核验 | 确认模型必须遵循的真实结构和尺寸 | 无 |
| P0 | Blender 环境 | 确认本地 Blender 可执行并建立资产文件 | 无 |
| P0 | 网页项目骨架 | 能启动 Three.js 场景和资源加载 | 无 |
| P0 | 外部真实感模型 | 形成可点击的三舱外部总览 | 资料核验、Blender 环境 |
| P0 | 标签和热点 | 文字、模型和 `moduleId` 正确对应 | 网页项目骨架、外部模型 |
| P0 | 内部场景 | 三个舱段有独立内部入口 | Blender 环境、场景配置 |
| P0 | 状态切换 | 实现总览、过渡、内部、返回流程 | 标签和内部场景 |
| P1 | 真实性复核 | 对照资料检查形体、比例、颜色和设备 | 外部模型、内部场景 |
| P1 | 性能和兼容性 | 保证浏览器中稳定运行 | 完整交互闭环 |

## 2. P0-01：建立真实资料登记表

### 任务

从官方公开资料中整理空间站外观、舱段关系和关键设备，不能直接使用没有来源的网络模型或宣传图作为事实依据。

### 资料范围

- 天和核心舱、问天实验舱、梦天实验舱的外部构型。
- 三舱相对连接关系和主要对接口。
- 太阳翼、大小机械臂、外部载荷平台的基本位置和形态。
- 舱体长度、最大直径等比例参考。
- 天和、问天、梦天的功能差异，用于内部场景布置。

### 推荐来源

优先使用总设计文档参考资料中的中国国家航天局、中国载人航天工程网和央视公开资料。每条资料登记：

- 标题和发布机构
- 原始 URL
- 发布日期和访问日期
- 支撑的具体模型或文案
- 是否允许作为公开展示素材的参考
- 备注和不确定点

### 完成标准

- [ ] 建立 `references/space-station-sources.md` 或等效资料表。
- [ ] 每个外部主要部件至少有一条可追溯来源。
- [ ] 明确哪些内容是公开事实，哪些内容是近似建模，哪些内容是游戏规划。
- [ ] 未公开的内部布局不标注为真实工程平面图。

## 3. P0-02：确认本地 Blender 环境

### 任务

确认 Blender 是可执行的安装版或便携版，并记录版本和路径。当前已确认本机 Blender 可执行文件位于 `D:\DeskTop\blender-5.2.3\blender-5.2.3\blender.exe`，版本为 `5.2.3 LTS Release Candidate`。

### 操作步骤

1. 在开始菜单、下载目录和用户指定目录中定位 `blender.exe`。
2. 使用完整路径执行：

   ```powershell
   & "C:\实际路径\blender.exe" --background --version
   ```

3. 记录 Blender 主版本，后续所有导出均使用同一主版本。
4. 在项目中约定 Blender 源文件目录，不把临时自动保存文件提交到项目。

### 完成标准

- [x] 能输出 Blender 版本。
- [x] 已记录 Blender 可执行文件路径和版本。
- [ ] 确认 Blender 使用米制单位。
- [ ] 确认 Blender 为 Z 轴向上，并记录导出到 Three.js 的坐标约定。
- [ ] 建立一个可打开的 `station-blockout.blend`。

## 4. P0-03：建立 Blender 资产规范

### 任务

在正式建模前固定集合、对象命名、原点、尺度和自定义属性，保证模型替换时不需要重写网页交互。

### 集合和对象命名

```text
STA_Tianhe_Exterior
STA_Wentian_Exterior
STA_Mengtian_Exterior
OVW_Station_Assembly
INT_Tianhe
INT_Wentian
INT_Mengtian
HOTSPOT_Module_Tianhe
HOTSPOT_Module_Wentian
HOTSPOT_Module_Mengtian
ENTRY_Tianhe
ENTRY_Wentian
ENTRY_Mengtian
SPAWN_Tianhe
SPAWN_Wentian
SPAWN_Mengtian
COLLISION_*
```

### 必须遵守的规范

- 单位使用米。
- 外部、内部、热点和碰撞体分集合管理。
- 原点和旋转方向在导出前固定。
- 热点对象必须设置唯一 `moduleId`。
- 出生点和镜头目标必须是单独的空对象或标记对象。
- 不把外部壳体、内部墙体和可交互设备导出为不可拆分单一网格。

### 完成标准

- [ ] Blender Outliner 中集合结构符合约定。
- [ ] 三个舱段的外部对象可单独隐藏和显示。
- [ ] 热点、入口、出生点和相机目标可被网页端按名称查找。

## 5. P0-04：制作中国空间站外部真实感灰盒

### 任务

先制作比例正确的外部灰盒，再逐步增加材质和设备细节。灰盒可以简化，但三舱拓扑不能随意修改。

### 建模顺序

1. 建立全局原点和三舱中心线。
2. 按公开资料确定天和、问天、梦天的相对连接关系。
3. 建立舱体外壳和节点连接。
4. 加入太阳翼的大致方向和展开关系。
5. 加入大小机械臂、外部平台和主要对接口的简化占位。
6. 设置三个舱段的热点、镜头目标和入口标记。
7. 用官方图片逐项对照轮廓、颜色分区和部件位置。

### 真实性要求

- 外观整体必须能被辨认为中国空间站，而不是泛化的科幻空间站。
- 不使用蓝紫霓虹灯带、夸张对称结构或不存在的巨大外部设备。
- 太阳翼、机械臂和外部载荷平台不能只作为随机装饰。
- 未确认的细节使用克制的近似，不自行添加具有事实含义的标识。
- 模型旁或资料面板中区分“官方资料依据”和“游戏规划示意”。

### 完成标准

- [ ] 默认镜头能同时看清三舱。
- [ ] 三舱相对关系和主要外部轮廓通过资料复核。
- [ ] 每个舱段都有可命中的热点代理。
- [ ] 没有使用无法说明来源的外部模型作为最终资产。

## 6. P0-05：制作三个内部灰盒入口

### 任务

为三个舱段建立能被识别的最小内部空间，不在此阶段追求完整设备复原。

### 内部最低内容

- 入口过渡区域。
- 主通道或主要工作空间。
- 墙体、舱门和基础空间边界。
- 2 至 3 个代表性设备占位。
- 该舱段的 `SPAWN_*` 出生点。
- 与外部入口对应的 `ENTRY_*` 标记。

### 内容边界

- 天和优先体现生活、工作和节点连接。
- 问天优先体现生命科学实验和航天员气闸方向。
- 梦天优先体现实验机柜和货物气闸方向。
- 具体房间位置没有公开依据时，标记为游戏布局。

### 完成标准

- [ ] 三个内部场景可以分别启用和隐藏。
- [ ] 三个出生点均不在墙体、设备或舱门内部。
- [ ] 从入口方向可以判断当前舱段。
- [ ] 关键布局有资料备注或“游戏规划”标识。

## 8. P0-07：实现总览、标签和统一选中逻辑

### 任务

实现外部相机、空间锚定文字、模型射线检测和统一的 `selectModule(moduleId)`。

### 行为要求

- 标签跟随三维锚点，而不是固定在屏幕角落。
- 悬停标签时高亮模型热点。
- 悬停模型时高亮标签。
- 点击标签和点击模型都只产生一个 `moduleId`。
- 进入过渡时禁用其他热点和相机操作。

### 完成标准

- [x] 点击“天和核心舱”绝不会进入其他舱段。
- [x] 三个标签在环绕和缩放时位置正确。
- [x] 选中反馈不会遮挡空间站主体。
- [ ] 标签重叠时有偏移、隐藏或排序策略。

## 9. P0-08：实现镜头过渡和内部切换

### 任务

根据 `moduleId` 找到对应的 `cameraTarget`、`entryPoint`、`interiorScene` 和 `spawnPoint`，完成总览到内部的切换。

### 推荐时序

```text
点击标签
  -> 状态切换为 TRANSITION
  -> 相机移动到外部入口
  -> 淡入/遮挡
  -> 隐藏外部遮挡模型
  -> 显示对应内部场景
  -> 相机放置到 spawnPoint
  -> 状态切换为 INTERIOR
```

### 完成标准

- [x] 三个标签分别进入正确的内部场景。
- [x] 镜头不直接穿透模型。
- [x] 过渡期间不能重复触发其他舱段。
- [x] 内部场景不残留错误舱段的模型。
- [x] 进入后页面明确显示当前舱段名称。

## 12. P1-02：性能和浏览器验收

首版先以桌面 Chrome 和 Edge 为目标环境。后续再决定是否支持移动端。

检查项目：

- [ ] 首次加载有进度提示。
- [ ] 外部总览和内部切换没有明显长时间卡顿。
- [ ] 模型不会因重复进入而重复加载或重复添加。
- [ ] 进入和返回至少连续测试 10 次。
- [ ] 窗口缩放、刷新和切换标签页后状态正常。
- [ ] 低性能设备上仍能完成点击和场景切换。

## 13. 推荐执行顺序

```text
1. 整理官方资料和真实性登记表
2. 定位 Blender 并建立资产规范
3. Blender 制作外部三舱灰盒
4. Blender 制作三个内部入口灰盒
5. 创建网页项目和资产清单
6. 实现总览相机和文字标签
7. 实现模型/文字统一选中
8. 实现镜头过渡和内部切换
9. 实现返回、错误和重置
10. 用真实资料复核模型并替换精细资产
11. 做浏览器、性能和连续切换验收
```

不要在第 3 步之前制作大量设备细节，也不要在三舱拓扑和 `moduleId` 绑定稳定前批量制作精细内部资产。

## 14. 当前阶段完成定义

用户能够完成以下操作时，认为本阶段完成：

```text
打开网页
  -> 看到接近中国空间站真实构型的三舱外部模型
  -> 点击“问天实验舱”文字
  -> 镜头移动到问天入口
  -> 进入问天内部灰盒
  -> 返回总览
  -> 点击“梦天实验舱”文字
  -> 正确进入梦天内部灰盒
```

只有在这个闭环稳定，并且外观模型完成资料复核后，才进入精细材质、设备交互和零重力移动阶段。
