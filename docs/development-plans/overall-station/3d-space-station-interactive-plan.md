# 3D 空间站交互场景实现计划（交互原型版）

> 文档状态：交互闭环原型记录。外部真实感建模请以 `3d-space-station-exterior-realism-plan-v2.md` 为准；任务执行请以 `3d-space-station-exterior-realism-task-breakdown.md` 为准。当前程序化灰盒不作为最终外观资产。

## 1. 结论与首版目标

这个方向合理，适合作为项目的第一条可运行闭环：

```text
外部三维总览
  -> 点击舱段文字或对应三维模型
  -> 聚焦目标舱段
  -> 镜头过渡
  -> 显示对应舱段内部
  -> 点击返回总览
```

首版先验证场景切换和交互关系，不加入零重力移动、实验任务、机械臂操作和后端服务。

首版必须完成：

- 浏览器中显示可旋转、可缩放的空间站外部三维模型。
- 显示“天和核心舱”“问天实验舱”“梦天实验舱”三个空间锚定文字标签。
- 点击文字标签或对应的三维舱段，都能选中同一个舱段。
- 点击后镜头平滑聚焦，并切换到对应舱段的内部场景。
- 内部场景至少先使用可行走空间的灰盒模型，三个舱段均有独立出生点。
- 提供返回总览按钮，返回后恢复外部模型、镜头和标签状态。
- 加载中、加载失败和重复点击时有明确反馈。

## 2. 交互方式的确定

文字标签可以作为主要入口，但标签不能只是屏幕上的固定按钮。每个标签必须绑定一个稳定的 `moduleId`，并与空间站模型热点、镜头目标、内部场景和出生点使用同一份配置。

建议采用以下行为：

1. 鼠标悬停文字或三维舱段时，两者同时高亮。
2. 点击文字或模型热点后，直接进入对应舱段；首版暂不增加二次确认面板。
3. 镜头先移动到外部舱段入口，再通过淡入或遮挡切换到内部，避免镜头直接穿过舱壁。
4. 进入内部后隐藏外壳的遮挡部分，启用该舱段内壁、设备和碰撞灰盒。
5. 点击“返回总览”后恢复外部摄像机和三舱显示。

后续如果需要介绍舱段功能，可以在直接进入前增加预览面板，但不能改变 `moduleId` 这条数据关系。

## 3. 推荐技术方案

当前仓库只有设计文档，因此建议从一个新的网页项目开始：

- 构建工具：Vite
- 开发语言：TypeScript
- 3D 引擎：Three.js
- UI：React（也可以先用原生 DOM，取决于首版开发速度）
- 模型格式：GLB/GLTF
- 相机过渡：统一的 TransitionController，可使用 Tween/GSAP 或自有插值函数
- 首版数据存储：本地配置文件，不接后端

首版不要求高精度工程仿真。优先使用低面数灰盒验证空间关系，之后再替换为 Blender 导出的精细 GLB。

## 4. 场景和状态设计

### 4.1 状态

```text
LOADING       初始加载模型和配置
OVERVIEW      外部总览，可旋转和缩放
TRANSITION    镜头过渡，暂时屏蔽重复输入
INTERIOR      显示选中舱段内部
ERROR         资源加载失败或场景初始化失败
```

首版状态转换：

```text
LOADING -> OVERVIEW
LOADING -> ERROR
OVERVIEW -> TRANSITION
TRANSITION -> INTERIOR
TRANSITION -> ERROR
INTERIOR -> TRANSITION
TRANSITION -> OVERVIEW
```

### 4.2 三维场景组织

建议所有外部和内部模型使用统一世界坐标，不在进入舱段时重新计算空间位置。

```text
StationRoot
├── OverviewExterior
│   ├── STA_Tianhe_Exterior
│   ├── STA_Wentian_Exterior
│   ├── STA_Mengtian_Exterior
│   └── HOTSPOT_Module_*
├── InteriorScenes
│   ├── INT_Tianhe
│   ├── INT_Wentian
│   └── INT_Mengtian
├── Labels
└── TransitionMarkers
```

内部模型可以先全部加载后按状态切换显隐；模型变大后再改为按舱段延迟加载。

## 5. 核心配置数据

不要把舱段名称、标签位置和场景切换逻辑分散写在组件中。建议统一维护类似以下配置：

```ts
type StationModule = {
  id: 'tianhe' | 'wentian' | 'mengtian';
  name: string;
  exteriorHotspot: string;
  labelAnchor: [number, number, number];
  cameraTarget: [number, number, number];
  entryPoint: [number, number, number];
  interiorScene: string;
  spawnPoint: [number, number, number];
};
```

需要保持的约束：

- `id` 全局唯一且后续模型替换时不变。
- 文字标签、三维热点和内部场景只能通过 `id` 关联。
- 标签位置跟随对应舱段或锚点对象，而不是写死在屏幕坐标。
- 每个舱段都必须配置镜头目标、入口点、内部场景和出生点。

## 6. 分阶段实施

### 阶段 0：项目骨架

交付内容：

- 创建 Vite + TypeScript + Three.js 项目。
- 建立 `SceneStateManager`、`StationOverviewController`、`TransitionController` 的基本接口。
- 建立统一的渲染循环、窗口缩放和资源加载入口。
- 建立错误提示和加载提示。

验收标准：

- 浏览器可以启动项目并显示基础场景。
- 窗口大小变化不会破坏画面比例。
- 加载失败不会出现空白页面，用户能看到错误状态。

### 阶段 1：空间站外部灰盒

交付内容：

- 使用基础几何体搭建天和、问天、梦天三舱的外部关系。
- 加入太阳翼、节点连接和主要外部结构的简化占位。
- 设置总览摄像机的默认位置、旋转中心、最小/最大缩放距离。
- 给三个舱段设置独立的 `HOTSPOT_Module_*` 射线代理。

验收标准：

- 三舱关系清晰可见，模型不会被相机裁切。
- 鼠标拖动可以环绕观察，滚轮可以缩放。
- 相机不会穿过空间站或缩放到不可用距离。

### 阶段 2：文字标签和模型热点

交付内容：

- 在三个舱段旁添加空间锚定标签。
- 标签和模型热点共用同一 `moduleId`。
- 悬停标签时高亮对应模型，悬停模型时高亮对应标签。
- 点击两种入口时都调用统一的 `selectModule(moduleId)`。

验收标准：

- 点击“天和核心舱”不会进入问天或梦天。
- 标签在相机旋转、缩放时仍跟随对应舱段。
- 标签不会遮挡关键模型；标签重叠时有简单的偏移或隐藏策略。

### 阶段 3：内部灰盒和镜头过渡

交付内容：

- 为三个舱段建立最小可识别内部灰盒。
- 每个内部场景至少包含：入口、主通道、墙体、主要设备占位和出生点。
- 点击舱段后进入 `TRANSITION`，沿入口和目标点移动镜头。
- 过渡期间禁用重复点击和相机拖动。
- 过渡结束后进入 `INTERIOR`，只显示对应内部场景。

验收标准：

- 点击三个标签分别进入正确的内部灰盒。
- 镜头不会直接穿透外壳，也不会出生在墙体或设备内部。
- 过渡期间不会重复触发多个舱段。
- 进入内部后能明显判断当前所在舱段。

### 阶段 4：返回总览和异常恢复

交付内容：

- 内部场景显示“返回总览”按钮。
- 返回时恢复外部模型、标签、默认相机和 `OVERVIEW` 状态。
- 增加模型加载失败、过渡中断和场景初始化失败的处理。
- 增加“重置场景”入口，避免玩家卡在错误状态。

验收标准：

- 三个舱段均可重复进入和返回。
- 返回后不会残留上一个舱段的模型、标签或相机状态。
- 刷新页面后可以重新从总览开始。

### 阶段 5：替换精细资产

交付内容：

- 用 Blender 资产替换外部灰盒和内部灰盒。
- 保持已有 `moduleId`、对象命名和出生点配置不变。
- 外观模型、内部模型和碰撞模型分离导出。
- 增加材质、灯光、标识和基础音效。

验收标准：

- 更换模型不需要重写交互逻辑。
- 总览与内部切换不出现外壳遮挡或模型残留。
- 主要浏览器和目标设备上保持稳定帧率。

## 7. 推荐的代码模块

```text
src/
├── app/
│   └── App.tsx
├── scene/
│   ├── SceneStateManager.ts
│   ├── StationOverviewController.ts
│   ├── InteriorSceneController.ts
│   └── TransitionController.ts
├── interaction/
│   ├── RaycastInteraction.ts
│   ├── ModuleSelection.ts
│   └── InteractableRegistry.ts
├── data/
│   └── stationModules.ts
├── ui/
│   ├── LoadingOverlay.tsx
│   ├── ModuleLabel.tsx
│   └── NavigationControls.tsx
└── assets/
    └── asset-manifest.ts
```

`ModuleLabel` 不直接操作摄像机或模型显隐，只发出 `moduleId`；状态管理器统一决定后续转换。这样后续增加右侧预览面板或任务入口时，不需要修改三维场景逻辑。

## 8. 首版验收清单

- [ ] 页面打开后先显示外部三维空间站总览。
- [ ] 三个舱段都有清晰可读的文字标签。
- [ ] 标签和三维模型热点一一对应。
- [ ] 点击任意标签只会进入对应舱段。
- [ ] 镜头过渡期间不会重复触发操作。
- [ ] 三个舱段各有独立内部灰盒和出生点。
- [ ] 内部场景不会显示错误舱段或残留外壳。
- [ ] 可以从内部返回总览，并再次进入其他舱段。
- [ ] 加载中、加载失败和错误恢复状态可见。
- [ ] 至少在 Chrome 和 Edge 桌面端完成一次完整回归测试。

## 9. 首版明确不做的内容

- 第一人称零重力自由移动。
- 扶手抓握、碰撞物理和 EVA 活动。
- 实验参数模拟和机械臂控制。
- 账号、多人、后端和云端存档。
- 未经验证的内部工程布局复原。
- 复杂访问飞船、任务时间线和实时轨道模拟。

这些内容等“总览—点击—进入—返回”的闭环稳定后，再按任务优先级增加。

## 10. 第一阶段完成定义

当用户可以在浏览器中完成下面的操作时，认为第一阶段成功：

```text
打开页面
  -> 看到完整三舱外部模型
  -> 点击“问天实验舱”文字
  -> 镜头聚焦问天并进入问天内部灰盒
  -> 点击返回总览
  -> 点击“梦天实验舱”文字
  -> 正确进入梦天内部灰盒
```

完成这个闭环后，再进行精细建模和第一人称体验开发，能够最大限度避免因为舱段拓扑、标签绑定或场景状态设计错误而返工。
